# 模块交接与整合记录

交接不是“发个链接”，而是**接收方在自己的环境里跑通并写下结果**。接收方没跑通就不算交接完成。

## 1. 交接矩阵

| 交接方 | 接收方 | 交接内容 | 接收方验收方式 | 对应任务 |
| --- | --- | --- | --- | --- |
| A | 全员 | 需求、数据字典、验收清单、接口约束 | 每人确认自己知道输入、输出和截止时间，在看板卡上回复“已读 + 我的输入/输出是…” | A-01…A-04 |
| B | C | CSV/JSON、来源登记、字段说明、核对状态 | C 运行 `python scripts/import_data.py --file data/verified/evidences.csv --dry-run`，错误记录可读且可修复 | B-06 → C-03 |
| C | D | OpenAPI、示例 JSON、错误码、接口地址 | D 不接数据库，仅用 API 完成页面展示；对每个字段能在 `api-contract.md` 找到定义 | C-04/C-05 → D-02 |
| C | E | 数据库地址、迁移脚本、健康检查接口 | E 能在服务器上从零初始化并恢复数据库，`/api/health` 返回 ok | C-01/C-06 → E-05 |
| E | 全员 | 本地启动方式、服务器地址、模型配置、测试报告 | 所有人从同一地址和同一命令启动或访问，结果一致 | E-05/E-06 |
| D | A | 页面截图、演示路径、异常状态截图 | A 按 `demo-script.md` 完整走通流程 | D-06 → A-06 |

### 交接卡怎么开

用「开发任务卡」建 issue，标题写成 `[HANDOFF] B→C 首批证据数据包`，打上 `handoff` 标签，正文包含：

```markdown
交接方 / 接收方：
交接内容（路径或地址）：
接收方验收命令：
接收方验收结果：            <-- 由接收方填写，必须是真实执行结果
未通过时的原因与修复责任人：
```

接收方填完验收结果并 @ 交接方后，这张卡才能关闭。**没有“验收结果”这一行的交接卡不允许关闭。**

## 3. 交接纪律

- 交接物必须在 `main` 上可获取（合并后的路径或部署地址），不允许“在我本地能跑”。
- 数据类交接必须附数量统计（总条数 / 已核对 / 有争议 / 待核对），数字与 `scripts/validate_data.py` 输出一致。
- 接口类交接必须通过 `docs/api-contract.md` 的字段定义；口头约定的新字段无效。
- 交接卡连续两次验收不通过，由 A 介入并重新划分范围（可能砍掉该功能，转入期末）。
