# 任务看板与每日节奏

看板地址：<https://github.com/users/Jerry-Ca/projects/1>（名称「姓氏郡望与家族迁徙寻根系统 · 三日冲刺看板」）
看板由 `node scripts/setup_board.mjs --apply` 创建与同步（幂等）：列、`角色`、`冲刺日` 三个字段和 30 张卡都来自本文件的规则，
新增任务后重跑一次即可把新卡加入看板。

看板是唯一进度事实来源。口头说“做完了”不算，看板卡片状态 + PR 合并才算。

## 1. 列与流转

| 列 | 进入条件 | 离开条件 |
| --- | --- | --- |
| `Backlog` | 任务已在 `tasks.json` 中定义 | 负责人认领并确认依赖已满足 |
| `Ready` | 依赖满足、验收标准清晰 | 分支已建、开始写代码 |
| `In progress` | 已建分支（`feat/…`、`data/…`） | 提交 PR |
| `Review` | PR 已开，CI 运行中/已通过 | 评审通过且 CI 全绿 |
| `Blocked` | 依赖未交付或被接口变更卡住 | 阻塞解除，回到 `In progress` |
| `Verify` | PR 已合并，等待 A 按 `acceptance.md` 验收 | 验收通过 |
| `Done` | 验收通过，交付物可访问 | — |

卡在 `Blocked` 超过 2 小时的，必须在看板写明阻塞对象并 @ 对方；这是每日整合的第一议题。

## 2. 自定义字段

- `角色`：A / B / C / D / E——用于“按人”视图。
- `冲刺日`：Day1 / Day2 / Day3——用于“按日”视图与每日清盘。

## 3. 标签

标签定义在 [labels.json](labels.json)，由 `node scripts/seed_github.mjs --apply` 创建。

| 前缀 | 取值 | 用途 |
| --- | --- | --- |
| `type/` | feature, data, doc, deploy, test, infra | 交付类型 |
| `owner/` | A, B, C, D, E | 主责人（与看板字段互为兜底） |
| `day/` | 1, 2, 3 | 冲刺日 |
| `prio/` | p0, p1, p2 | p0 = 阻塞当天验收 |
| 状态 | `blocked`, `handoff`, `data-review`, `needs-verification`, `wontfix-now` | 流程状态 |

## 4. 里程碑

| 里程碑 | 覆盖任务 | 当日验收 |
| --- | --- | --- |
| `M1 骨架与首条闭环（Day1）` | A-01…A-05, B-01, B-02, C-01…C-03, D-01, E-02 | 输入「李」能从前端看到数据库里的真实证据并展开来源 |

## 5. 任务依赖（谁在等谁）

```
A-03 ──► A-04 ──► D-01
          │
A-03 ──► C-02 ──► C-03 ──► B-03 ──► B-06
                  │         │
                  └► C-04 ──┴► C-05 ──► E-01 ──► E-03 ──► E-04
                       │                 ▲
                       └► D-02 ──► D-03 / D-04 / D-05        E-02 ──┘
B-01 ──► B-02 ──► B-03          C-01 ──► E-05 ──► D-06 / C-06 ──► E-06 ──► A-06
B-01 ──► B-05 ────────────────► B-06
```

关键路径：`A-03 → C-02 → C-03 → B-03 → B-06 → C-04 → C-05 → E-01 → E-03 → E-04 → E-06 → A-06`。
关键路径上的任务一律 `prio/p0`，任何人不能占用这些任务的主责人做别的事。

## 6. 每日节奏

| 时间 | 动作 | 负责人 |
| --- | --- | --- |
| 09:00 | 15 分钟站会：昨天完成 / 今天计划 / 卡在哪 | A 主持 |
| 12:00 前 | 上午任务提交 PR（不要求合并） | 全员 |
| 14:00 | A 巡检看板：`Blocked` 与 `p0` 优先处理 | A |
| 18:00 | 各自合并已完成部分到 `main` | 各主责人 |
| 21:00 | 整合检查点：合并当天分支、过一遍 `acceptance.md` 当日条目 | A + 全员 |
| 22:00 前 | 更新看板状态，未完成项拆成次日 issue | 全员 |
| Day3 12:00 | 冻结 `main`（只接受 P0 修复），打标签 `v1.0.0` | A |

## 7. 每天结束时的三问

1. 接口字段有没有变？（变了就在 PR 里同步 `docs/api-contract.md` 并 @D、@E）
2. 谁的交付物还没接上？（写进 `handoff.md` 的整合记录）
3. 明天第一件事是什么？（每人第二天开工前看板卡必须已 `Ready`）
