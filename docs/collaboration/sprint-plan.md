# 三天冲刺日程（按人 × 上下午）

每一天结束时都必须形成一个可运行的阶段版本——不是“第一天写代码、第二天写代码、第三天上线”，而是每天都完成一条从数据到页面的闭环。
每个时间段后面的编号是 [tasks.json](tasks.json) 中的任务编号，也就是看板卡片与 issue。

## Day1 建立正式骨架并跑通第一条闭环

**当天验收：输入「李」，前端通过 API 从数据库读到真实证据；证据可展开看到文献来源；项目可在本地启动。**

| 成员 | 上午 | 下午 | 当天必须交付 |
| --- | --- | --- | --- |
| A | 确认功能边界；建任务看板（`seed_github.mjs --apply`）；写需求与验收清单 `A-01 A-02`；冻结首批演示流程 `A-06`预备 | 审查数据字典 `A-03`；确定 API 字段 `A-04`；协调 B/C/D 对齐；21:00 整合第一版 `A-05` | requirements、acceptance、data-dictionary、第一版整合记录 |
| B | 确定首批 8—10 个姓氏与来源范围；建来源登记表 `B-01`；整理第一批候选证据 `B-02` | 回看原文；完成 10—15 条“已核对”证据（`B-03` 开工）；按模板交给 C | source_register、首批 verified 数据、核对说明 |
| C | 初始化 FastAPI / SQLAlchemy / Alembic / PostgreSQL `C-01`；创建表和迁移 `C-02` | 完成导入校验 `C-03`；导入 B 的首批数据；实现 health 与姓氏总览 API（`C-04` 开工） | 数据库迁移、导入脚本、首个可调用 API |
| D | 搭建 React/Vite 页面、路由与基础样式；建立搜索页 `D-01` | 接入总览 API `D-02`；完成一张证据卡片与一个来源详情 `D-03`；处理加载状态 | 输入「李」能显示真实证据的前端页面 |
| E | 准备服务器与模型密钥；建 RAG / 部署 / 测试目录；写提示词草稿与 Prompt Log 第 1 条 `E-02` | 完成精确检索（`E-01` 开工）；建立本地启动脚本与健康检查 | 本地一键启动、健康检查、Prompt Log 第 1 条 |

## 三天内明确不做的事

- 后台审核界面、更多文献版本、复杂地图（转入期末）。
- PPT 与技术报告（三天只需保存 Prompt Log、迭代截图、分工记录与部署说明）。
- 为 100 个姓氏凑数：宁可用 20—30 个资料丰富的姓氏做 100+ 条可核验证据，也不要 100 个没有出处的姓氏。
