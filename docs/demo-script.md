# 演示脚本（最终验收用）

对应任务 **A-06**。五个固定问题从头到尾走一遍，覆盖四项硬性输出与六种异常状态。演示前 30 分钟按第 4 节彩排一次。

## 1. 演示前准备

- [ ] 公网地址可访问，`/api/health` 返回 `ok`
- [ ] 已备份数据库（`scripts/backup_db.py`），dump 在手
- [ ] 数据冻结在 `v1.0.0`，无人再改数据
- [ ] 桌面浏览器与手机各一台/一台模拟，均连非校园网（4G）备测
- [ ] 准备好“模型关闭”演示：另一个终端可随时把 `DEEPSEEK_API_KEY` 清空并重启后端

## 2. 五个固定问题

### 问题 1：已收录姓氏的完整查询（对应硬性输出 1—4）

1. 打开首页，输入 `李`，点击查询。
2. 指出首屏四块：最早书证、历史郡望、迁徙线索、语料审计。
3. 展开最早书证卡片，逐项念出：**年代、书名、卷次、原文摘录、来源链接、核对状态**。
4. 点开来源详情，说明版本、平台、访问时间。

> 讲述要点：“‘最早’是**当前语料中**可以确认的最早，不是历史上最早——这句话是系统自动区分的，因为证据只能支持到这里。”

### 问题 2：未收录姓氏（异常状态 1）

1. 输入一个语料中确实没有的姓氏（用 B 提供的对照清单）。
2. 指出页面显示的是**已查询的语料范围 + 查询词 + 未命中原因**，不是空白页。

> 讲述要点：“查不到也是一种结论，所以我们把‘查过哪些语料、用了什么词、为什么没结果’当作正式功能来做。”

### 问题 3：争议与复姓（异常状态 5 + 输入处理）

1. 输入被标记为 `disputed` 的姓氏，展示**并列**的多种说法与各自来源。
2. 强调界面没有默认选中项，也没有“推荐”标记。
3. 输入复姓 `欧阳`，说明别名/异体匹配与规范姓氏的对应关系。

> 讲述要点：“有争议的时候，我们不做裁判，只负责把每种说法的出处摆清楚。”

### 问题 4：证据问答（智能算法 + 数据真实性）

1. 针对问题 1 的姓氏提问，例如“这个姓氏的郡望在哪些文献中有记载？”
2. 指出回答中的**证据编号**（形如 `[EV-LI-001]`），点击编号可跳回对应证据卡片。
3. 再问一个资料范围外的问题（例如“某位历史人物的家族细节”），展示系统回答“**当前资料不足以确认**”。

> 讲述要点：“模型的输出被强制绑定到证据编号，编不出引用就不允许作为结论出现。”

### 问题 5：模型关闭后的降级（异常状态 4 + 工程深度）

1. 在另一个终端清空模型 Key 并重启后端。
2. 刷新页面：结构化证据、时间线、关系图**全部正常**，只有智能摘要区显示“暂不可用”。
3. 再用同一地址从手机打开，同样可用。

> 讲述要点：“结构化数据是主干，模型只是增强。模型挂掉不影响查证据。”

## 4. 彩排与预案

| 风险 | 预案 |
| --- | --- |
| 公网临时不可访问 | 本地 `bash scripts/dev.sh` 起一套同源环境，用本地地址演示；手机改连同一局域网 |
| 模型接口超时 | 直接进入问题 5 的降级演示，说明这是设计好的行为 |
| 数据没导完 | 提前一天冻结数据；演示用备份 dump 恢复后再导 |
| 页面缓存导致看到旧数据 | 硬刷新（Ctrl+F5）；接口层 `Cache-Control` 只缓存 60 秒 |
| 演示者紧张讲错措辞 | 只念卡片上写好的文案，不即兴解释历史事实——**不确定的内容一律说“当前语料中未找到”** |

## 5. 演示纪律

- **不即兴补充历史事实**。任何卡片上没有的内容，一律回答“这不在我们的语料范围内”。
- 不承诺期末未实现的功能，只说明“已列入期末计划”（见方案第十三节）。
- 演示中发现的缺陷当场记录到看板，演示后转为 issue，不口头答应立即修。
