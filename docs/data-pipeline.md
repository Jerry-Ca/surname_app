# 数据管线（从原始材料到可查询证据）

对应方案文档第六节，任务 **B-01 … B-06**。管线的存在本身就是挑战层“数据规模 + 数据真实性”的证据，因此每一步的产物都要留在仓库里。

## 1. 九步流程

| 步骤 | 做什么 | 工具 / 文件 | 负责人 | 产物 |
| --- | --- | --- | --- | --- |
| 1 建立来源登记表 | 记录书名、版本、平台、链接、授权状态、访问时间 | `data/source_register.csv` | B | 来源编号 `SRC-###` |
| 2 获取原始材料 | 优先公开古籍全文、可核验的书目与影像元数据 | `data/raw/` | B | 原始导入文件 |
| 3 清洗文本 | 统一空格、异体字标记、卷次写法与时间表达 | `data/cleaned/` | B | 清洗后 CSV |
| 4 生成候选记录 | 可由 Agent 从原文抽取候选字段，**但不直接发布** | `data/raw/*.candidates.csv` | B | 候选记录（全部 `pending`） |
| 5 人工核验 | 回看原文，确认书名、卷次、原文与语义 | `data/verified/` | B | 已核对证据 |
| 6 标记状态 | 填写已核对 / 有争议 / 链接待复查 / 已撤回 | `data/verified/*.csv` | B | 状态字段 |
| 7 导入数据库 | 字段校验 + 重复检测 + 外键检查 | `scripts/import_data.py` | C | `ingestion_jobs` 记录 |
| 8 建立索引 | 更新全文索引与向量索引 | `POST /api/admin/reindex` | E | 索引计数 |
| 9 保存日志 | 记录导入数量、失败数量、跳过原因、操作人 | `review_logs`、`ingestion_jobs` | B、C | 审计记录 |

**第 4 步与第 5 步之间的界线是项目的红线**：Agent 抽取的字段一律 `pending`，没有人工回看原文不得进入 `data/verified/`。

## 2. 目录约定

```
data/
├─ source_register.csv    来源登记表（B-01 交付物，手工维护 + 校验）
├─ corpus_searches.csv    语料审计（B-05 交付物）
├─ raw/                   原始与候选材料；.gitignore 忽略大文件，只提交候选 CSV
├─ cleaned/               清洗后的中间产物（可被 raw 重新生成）
├─ verified/              已人工核对的最终数据包（B-06 交付物，唯一可导入的目录）
└─ templates/             字段模板与示例（示例值明确标注为占位，不得直接使用）
```

只有 `data/verified/` 下的文件可以被 `scripts/import_data.py` 导入；导入 `raw/` 或 `cleaned/` 会被脚本拒绝。

## 3. 文件格式约定

- 编码：**UTF-8 with BOM**（`utf-8-sig`）。这样在 Windows 上双击用 Excel 打开不会乱码；脚本读入时两种都兼容。
- 分隔符：英文逗号；字段内含逗号时用双引号包裹（标准 CSV）。
- 换行：`\n`（见 [.gitattributes](../.gitattributes)）。
- 表头：第一行，列名严格使用 [data-dictionary.md](data-dictionary.md) 第 5 节的列名，不翻译、不加空格。
- 一行 = 一条原子证据。**不要把多条证据塞进一格**（例如“原文 1；原文 2”），否则无法单独核验。
- 时间列：整数年，公元前为负数；不确定就留空并填 `time_label`。

## 4. 每条证据的最低字段

见 [data-dictionary.md](data-dictionary.md) 第 5 节的完整表格。核心要求：证据编号、关联姓氏、事实类型、书名、作者、卷次/章节/页码、原文短摘录、来源链接、访问时间、核对状态、可信度、人工核验说明、操作人。**缺任一项不得进入 `data/verified/`**，CI 会拦截。

## 5. 数据状态规则

| 状态 | 何时使用 | 是否能被前端展示 |
| --- | --- | --- |
| 待核对 `pending` | 已发现候选记录，尚未回看原文 | 否（后端过滤） |
| 已核对 `verified` | 人工确认书名、卷次、原文与来源链接 | 是 |
| 有争议 `disputed` | 存在多个说法，全部保留，不自动合并 | 是，必须并列展示 |
| 链接待复查 `link_stale` | 文献记录保留，但原链接当前不可访问 | 是，必须提示 |
| 已撤回 `retracted` | 发现误引或无法证明，保留撤回原因 | 是，灰显且不作为结论 |

任何状态都不物理删除。状态变更必须写 `review_logs`（谁、何时、改了什么、为什么）。

## 6. 质量门禁

| 门禁 | 触发方式 | 检查内容 |
| --- | --- | --- |
| `validate_data.py`（CI `data-check`） | 每次 PR / push | 编号格式、必填字段、状态枚举、年份合法性、`disputed` 必须有 `dispute_group`、CSV 编码 |
| `import_data.py`（服务器/本地） | B 交付时先 `--dry-run` | 外键存在性、重复证据、空原文、非法年份、来源登记存在性 |
| A 的人工抽查 | 每天整合 | 每天随机抽 5—10 条，回看原文核对；Day3 抽查 ≥30 条 |
| 来源可用性复查 | Day3 上午 | 检查链接是否仍可访问，失效的改 `link_stale` 并保留元数据 |

`validate_data.py` 只做结构与完整性检查，**不能替代人工核验**——脚本无法判断摘录是否真的出自那本书。

## 7. 授权与合规

- 遵守各平台条款，只保存**短摘录 + 链接 + 元数据**，不整本转载受限内容。
- 每条来源在 `source_register.csv` 里记录 `license_status`（公有领域 / 平台条款允许 / 仅可短摘录 / 未知）；`unknown` 的来源只能留链接与书目信息，不得留长摘录。
- 课程文档列出的可用资源（维基文库、中华珍宝馆、识典古籍、书格、中华古籍资源库、全球汉籍影像开放集成系统、中国哲学书电子化计划、故宫博物院数字文物库、搜韵网、字统网、汉典等）使用时都必须标注来源。
- 短摘录的用途限于学术研究与教学演示，页面上保留出处与访问时间。

## 8. 常见坑

| 坑 | 后果 | 避免方式 |
| --- | --- | --- |
| 用 Agent 生成的书名/卷次直接入库 | 数据不可追溯，全项目失去可信度 | 红线：只进 `raw/`，人工回看原文 |
| 把多种说法合并成一句“综合来看” | 争议消失，违背验收第 5 项 | 用 `dispute_group` 并列保留 |
| 卷次写“见原文”“如前” | 无法核验 | 校验规则直接拦截 |
| 年份填“大约唐代” | 数据类型混乱 | 年份留空，改填 `time_label` |
| Excel 另存为 GBK | 中文乱码、CI 失败 | 统一 UTF-8 with BOM |
| 用截图代替摘录 | 无法检索、无法引用 | 必须落文字摘录 |
