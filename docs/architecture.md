# 总体技术架构

对应方案文档第三节与第七节。本文件解释**为什么这样分层**，以及每层出问题时怎么降级。

## 1. 分层与数据流

```
浏览器
  │  同源访问（Vite 开发代理 / Nginx 反代）
  ▼
React + Vite 前端            ← 只调用 /api/*，不读数据库、不直连模型
  │  HTTP + JSON
  ▼
FastAPI 后端（单进程，监听内部端口 8000）
  ├─ 姓氏标准化与别名匹配
  ├─ 结构化查询（SQLAlchemy → PostgreSQL）
  ├─ 全文检索（PostgreSQL FTS / pg_trgm）
  ├─ 向量检索（pgvector；缺失时降级为 JSON 向量列）
  ├─ RAG（检索 → 提示词 → DeepSeek → 证据编号校验）
  └─ 数据管线入口（导入脚本、重建索引）
  │
  ▼
PostgreSQL：结构化数据 + 审核记录 + 语料审计 + 向量片段
  │
  ▼
大陆地域云服务器（轻量应用服务器，2 核 4GB 起），只开放 80/443/22
```

## 2. 数据库决策

| 决策 | 内容 | 理由 |
| --- | --- | --- |
| 正式环境用 PostgreSQL | 不用 SQLite 作为生产库 | 网页要作为期末作品持续维护，需要并发、全文检索与扩展能力 |
| SQLite 仅本地调试 | `DATABASE_URL=sqlite:///./dev.db` | 让 D 与 E 在没有数据库时也能启动 |
| 事实与证据分离 | `evidences` ↔ `evidence_sources` ↔ `source_editions` ↔ `source_works` | 一条事实可有多个来源，一个来源可支持多条事实；这样才能保留争议 |
| 向量方案可降级 | 优先 pgvector；安装不稳定时用 JSON 列 + 应用层相似度 | 三天内不因扩展安装问题阻塞核心功能 |
| 状态而非删除 | 用 `verification_status` 表达撤回、争议、链接待复查 | 保留可追溯性（[../AGENTS.md](../AGENTS.md) 铁律 7） |

表结构见 [data-dictionary.md](data-dictionary.md) 第 2 节。

## 3. 模块边界（代码归属）

| 目录 | 主责 | 契约 |
| --- | --- | --- |
| `frontend/` | D | 消费 [api-contract.md](api-contract.md)，不假设数据库结构 |
| `backend/app/` | C | 对外暴露 `/api/*`，字段名与契约一致 |
| `backend/search/` | E | 被 C 的查询接口调用，返回带 `evidence_id` 的排序结果 |
| `backend/rag/` | E | 检索、提示词、校验、降级；不改数据库结构 |
| `migrations/` | C | 任何表结构变化只能通过迁移 |
| `data/` | B | 只提供数据文件，不直接写库（写库统一走 `scripts/import_data.py`） |
| `deploy/` | E | 反代、进程管理、启动与备份脚本文档 |

跨目录改动必须开 issue 请对方改，不允许“顺手一起改了”。

## 4. 降级矩阵（每一行都必须有测试）

| 失效项 | 系统行为 | 用户看到什么 | 负责 |
| --- | --- | --- | --- |
| DeepSeek 不可用 / Key 缺失 | `/api/ask` 返回 `answer_mode=degraded_no_model`，仍返回检索到的证据 | 结构化证据、时间线、关系图全部正常；智能摘要区显示“暂不可用” | E |
| Embedding 不可用 | 切换为姓氏精确匹配 + 全文检索 | 结果数量可能减少，页面不报错 | E |
| pgvector 未安装 | 向量检索走 JSON 列或直接跳过 | 同上 | E |
| 外部来源链接打不开 | 用已保存的来源元数据与人工核对的短摘录 | 显示“链接待复查”，书名卷次原文仍在 | B、D |
| 数据库不可用 | `/api/health` 返回 503 且 `status=down` | 页面显示服务不可用 + 重试入口 | C |
| 用户输入非法 | 400 + `INVALID_SURNAME_INPUT` | 输入框下方给出修正提示 | C、D |

## 5. 部署拓扑（三天阶段）

| 项目 | 三天目标 | 期末扩展 |
| --- | --- | --- |
| 服务器 | 大陆地域轻量应用服务器，2 核 4GB 起 | 按访问量扩容或拆分服务 |
| 访问方式 | 公网 IP + HTTP 同源访问 | 域名、ICP 备案、HTTPS |
| 后端 | FastAPI 监听内部端口，由 Nginx/Caddy 反代 | 进程管理、日志、监控、自动重启 |
| 数据库 | 云服务器上的 PostgreSQL | 独立云数据库、定期备份、主从 |
| 部署方式 | 脚本化安装、启动、备份、健康检查 | CI/CD 自动部署 |

端口只开 80、443、22；**数据库不暴露公网**；所有密钥只存在于服务器环境变量。
详细步骤见 [deployment.md](deployment.md) 与 [../deploy/README.md](../deploy/README.md)。

## 6. 技术选型的取舍说明（写进期末报告用）

- **不用前端直连模型**：Key 一旦进浏览器就是零成本泄露，且无法做证据编号校验。
- **不做纯向量库**：向量检索会漏掉书名、卷次这类精确查询；本项目以“可核验”为第一目标，因此精确匹配 + 全文检索是主干，向量是补充。
- **不用大模型生成候选事实**：Agent 可以从原文抽取字段，但只能进 `data/raw/`，必须人工回看原文才能进入 `data/verified/`。
- **不做现代人口分布反推古代迁徙**：方法论错误，写入需求非目标。
