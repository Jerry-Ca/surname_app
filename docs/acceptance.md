# 验收标准与验收清单

对应任务 **A-02**。A 在每天 21:00 的整合检查点按本文件逐条走；D 在自测时按第 2 节自测。
每条都写了**输入、期望页面表现、期望接口返回**——验收时三者都要看，只看页面不算通过。

## 1. 六类情况的验收步骤

### 1.1 已收录姓氏（正常路径）

- 输入：`李`（或任一已入库姓氏）
- 接口：`GET /api/surnames/李` → 200，`coverage.status = "in_corpus"`，`summary.earliest != null`
- 页面：最早书证区显示年代、书名、卷次、原文摘录、来源链接、核对状态；郡望与迁徙区有内容；语料审计区列出查过的语料与查询词
- 展开：任意证据卡片可展开看到来源详情（书名、版本、平台、访问时间、原文短摘录）
- **不通过的样子**：原文摘录缺失、卷次写“见原文”、来源只有平台名没有链接

### 1.2 未收录姓氏

- 输入：语料中确实没有的姓氏（B 提供的对照清单里的一个）
- 接口：200，`coverage.status = "not_in_corpus"`，各列表为空数组，`coverage.queried_corpora` 非空
- 页面：显示“已查询的语料范围 + 查询词 + 未命中原因”，**不是空白页**，且提供返回搜索的入口
- **不通过的样子**：404、空白页、只显示“无结果”四个字

### 1.3 复姓与异体/繁体输入

- 输入：`欧阳`（复姓）、以及同一姓氏的异体或繁体写法
- 接口：`match_type` 为 `compound` / `variant` / `alias`，`coverage.matched_surname` 指向规范名
- 页面：结果页顶部显示“你输入的是 X，对应规范姓氏为 Y”
- **不通过的样子**：复姓被拆成单字查询、繁体输入报错

### 1.4 存在争议

- 输入：B 标记了 `disputed` 的姓氏
- 接口：`commanderies` 或 `migrations` 中 `is_disputed = true` 的条目全部返回，带 `dispute_group`
- 页面：并列展示不同说法与各自来源、核对状态；界面**没有**默认选中项或“推荐”标记
- **不通过的样子**：只显示一种说法、把两种说法合并成一句话、按置信度自动隐藏低分说法

### 1.5 模型失败（降级）

- 操作：清空 `DEEPSEEK_API_KEY`（或断开模型网络）后重启后端
- 接口：`GET /api/health` → 200，`status = "degraded"`，`degraded` 含 `model_unavailable`；`POST /api/ask` → 200，`answer_mode = "degraded_no_model"`，`citations` 仍有证据
- 页面：结构化证据、时间线、关系图正常；仅智能摘要区显示“暂不可用”
- **不通过的样子**：整页空白、5xx、问答区把降级提示写成“系统错误”

### 1.6 来源链接失效

- 操作：把某条证据的 `source_url` 改为不可访问地址（或 `link_status=stale`）
- 接口：该证据仍返回，`sources[0].link_status = "stale"`，`verification_status = "link_stale"`
- 页面：保留书名、卷次、原文与访问时间，并显示“链接待复查”
- **不通过的样子**：整条证据消失、链接失效导致页面报错

## 2. D 的自测清单（提交 PR 前自己走一遍）

- [ ] 桌面宽度与手机宽度（375px）都能完成一次完整查询
- [ ] 加载中有骨架屏或 loading，不是白屏
- [ ] 空结果有解释文案，错误有重试按钮
- [ ] 长原文摘录不会撑破卡片（可折行、可展开）
- [ ] 页面文案没有把“当前语料中最早”写成“历史上最早”
- [ ] 没有任何地方出现 API Key 或模型直连

## 5. 验收结论怎么记录

验收不通过时，A 在对应 issue 上写：**不通过的步骤 → 实际看到的现象 → 责任模块 → 是否阻塞演示**，并打标签 `needs-verification`。
禁止用“基本可以”“问题不大”作为结论。
